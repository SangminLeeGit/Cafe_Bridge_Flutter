# Cafe Bridge 전체 화면 UI/UX 초안 맵

이 문서는 `flutter-app-improvement-plan.md`의 P0/P1 결정을 기준으로, 현재 Flutter 코드에서 접근 가능한 화면과 상태를 한눈에 확인하기 위한 설계 기준선이다. 기존 API, 모델, 권한 값, 비즈니스 로직은 변경하지 않고 진입 구조와 공통 화면 규칙만 정리한다.

## 진입 구조

```text
AppRoot
├─ 초기화 중: 앱 준비 로딩
├─ 비인증: 로그인 / 로그인 실패 / 오프라인 안내 / 초기 설정 필요
└─ 인증 후 MainLayout
   ├─ 홈: 오늘 상태 → 일별 상세
   ├─ 인사이트: 개요 / 매출 흐름 / 메뉴 인사이트
   ├─ 업무: 원가 / 상품 작업대 / 가격 반영 / 메뉴판 / 동기화
   ├─ 인력: 대시보드 / 캘린더 / 근무 / 급여 / 직원 (operator 이상)
   └─ 더보기: 터치키 / 앱 설정 / 배포 관리 (권한별 잠금 노출)
```

## 화면 목록과 상태

| 화면 | 주요 목적 | 하위 화면·탭 | 반드시 설계하는 상태 |
|---|---|---|---|
| 앱 초기화 | 세션·업데이트·캐시 준비 | 로딩 | 초기화 로딩 |
| 로그인 | 인증·서버 진입 | 연결 설정은 설정에서 접근 | 기본, 실패, 잠금/권한, 오프라인, 초기 관리자 미설정 |
| 홈 | 오늘 운영 상태를 빠르게 판단 | 최근 7일 → 일별 상세 | 로딩, 빈 DB, 오류, 캐시, 네트워크 실패 |
| 일별 상세 | 영업일 단위 매출·결제·영수증 확인 | 이전/다음 영업일 | 로딩, 빈 데이터, 오류, 캐시 |
| 인사이트 | 분석 결론을 먼저 확인 | 개요(월간/비교/트렌드), 매출 흐름(품목/시간대/요일/결제), 메뉴 인사이트(메뉴 작업대/예측/ABC) | 기간 선택, 로딩, 빈 데이터, 오류, 캐시 |
| 업무 허브 | 조회 업무와 실행 업무 분리 | 원가, 상품 작업대, 가격 반영, 메뉴판, 동기화 | 권한 잠금, 네트워크 실패 안내 |
| 원가 | 재료·레시피·원가율 조회/관리 | 대시보드/재료/레시피 → 상세/편집 | 로딩, 빈 목록, 오류, 권한/저장 실패 |
| 상품 작업대 | 상품 탐색·초안·실행 이력 | 메뉴 선택/작업 목록 → 상품 상세/가격 변경/신규 메뉴 | 로딩, 필터 빈 상태, 검증 실패, 권한, 실행 중/성공/실패 |
| 가격 반영 | 고위험 가격 변경 실행 | 상품 선택 → 가격 입력 → 검증/영향 확인 → 실행 → 결과/이력 | 입력 오류, 중복 실행, 권한, 진행 중, 성공, 실패/재시도 |
| 메뉴판 | 사이니지 초안 편집과 반영 | 카테고리/상품 편집 | 로딩, 빈 메뉴, 미저장 변경, 검증 실패, 확인 다이얼로그, 반영 중/결과 |
| 동기화 | 대상일 매출 수집·적재 | 대상일 선택 → 확인 → 작업 진행 → 적재 이력 | 로딩, 네트워크 실패, 중복 실행, 진행 중, 시간 초과, 실패/재시도 |
| 인력 | 일정·직원·급여 운영 | 대시보드/캘린더/근무/급여/직원 | operator 권한, 로딩, 빈 직원/근무, 폼 검증, 급여 미리보기/확정 |
| 터치키 | POS 표·배치 읽기 | POS 맵/탐색 | 로딩, 빈 구조, API 오류, operator 권한 |
| 앱 설정 | 연결·보안·업데이트·세션 | 서버/앱 업데이트/인증·캐시/비밀번호/관리자 상세 | 연결 확인 중/성공/실패, 저장 확인, 로그아웃 확인 |
| 배포 관리 | 릴리스·사용자·감사 확인 | 배포 패널/사용자/감사 로그 | admin 권한, 로딩, 빈 로그, 실패, 확인/롤백 안내 |

## 공통 화면 규칙

- 배경 `#F8FAFC`, 표면 `#FFFFFF`, 기본 글자 `#0F172A`, 보조 글자 `#475569/#64748B`, 경계 `#E2E8F0`, 주요 액션 `#0D9488`을 역할 토큰으로 사용한다.
- 페이지 패딩 16dp, 카드 간격 12dp, 섹션 간격 20dp, 카드 radius 14dp, 조작 영역 최소 44dp를 기본값으로 둔다.
- 청록은 선택·주요 실행·핵심 KPI에만 사용한다. 성공/경고/오류는 색상과 텍스트 레이블을 함께 보여준다.
- 3개 이상 입력 필드가 있거나 키보드·검증·저장이 필요한 변경은 다이얼로그가 아니라 전면 폼으로 구성한다.
- 고위험 실행은 `입력 → 검증 → 영향 요약 → 확인 → 백그라운드 작업 → 결과/재시도`를 공통 순서로 유지한다.
- 오프라인 캐시가 제공되는 조회 화면은 캐시 시각을 표시한다. 인사·급여·감사·인증 데이터는 캐시하지 않는다는 P0 정책을 유지한다.
- 권한이 없는 기능은 탐색 구조에서 숨기지 않고 잠금 상태와 필요한 역할을 표시하되 실행은 차단한다.

## 현재 구현에서 보존한 미해결 TODO

실제 역할별 사용 빈도, 감사 보존기간과 롤백 절차, 작업 취소/idempotency API, 지원 OS·기기 폭, 공식 브랜드 가이드는 계획서의 미결정 사항이다. UI 초안에서는 임의의 운영 정책이나 데이터를 만들지 않고 기존 API와 역할 모델을 사용한다.
